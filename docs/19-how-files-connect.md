# 19. Как файлы собираются в приложение

Представьте команду: один участник отвечает за данные, второй — за внешний вид карточки, третий — за переход между экранами. В React Native файлы тоже удобно разделять по ответственности.

## Цепочка нашего учебного приложения

```text
src/types/activity.ts       описывает Activity
        ↓
src/data/activities.ts      хранит массив Activity[]
        ↓
app/index.tsx               показывает список через FlatList
        ├──→ src/components/ActivityCard.tsx   одна карточка, props
        │
        └──→ Link c id
                  ↓
            app/activity/[id].tsx               детальная страница
                  ↑
            src/data/activities.ts              поиск по id

app/_layout.tsx              общая навигация Stack
```

**Почему так удобнее:** формат данных меняем в `types`, отображение карточки — в `components`, переход между страницами — в `app`. Не нужно собирать всё в одном файле.

## Пять важных связей

1. **`export` / `import`:** позволяют использовать значение из другого файла.
2. **`import type`:** импортирует описание TypeScript-типа, но не создаёт объект в приложении.
3. **`props`:** экран передаёт отдельный объект `activity` компоненту `ActivityCard`.
4. **`Link`:** при нажатии передаёт `id` в маршрут `/activity/[id]`.
5. **`useLocalSearchParams`:** детальный экран читает `id` и находит подходящий объект.

Откройте `app/index.tsx` и найдите `<ActivityCard activity={item} />`. Именно эта строчка связывает **экран со списком** и **универсальную карточку**.

## Что произойдёт, если добавить новое поле?

Например, добавьте сложность занятия:

- в `src/types/activity.ts` объявите `difficulty: "easy" | "medium"`;
- в `src/data/activities.ts` укажите сложность для каждого объекта;
- в `src/components/ActivityCard.tsx` выведите значение рядом с ценой;
- запустите `npm run typecheck`.

Теперь TypeScript подскажет, если вы изменили тип, но забыли обновить один из объектов.
