# 16. HTTP-запросы: от локального списка к FastAPI

До этого момента идеи лежали в `src/data/activities.ts`. Теперь представим, что список приходит от вашего собственного небольшого HTTP API.

`fetch` отправляет запрос, а `await` дожидается результата:

```typescript
const response = await fetch("http://localhost:8000/activities");
if (!response.ok) throw new Error("Сервер недоступен");
const data: unknown = await response.json();
```

`unknown` — хорошая привычка: JSON пришёл извне, TypeScript **не проверяет его в рантайме**. Нужна отдельная проверка полей или библиотека валидации.

В заготовке есть `src/api/activities.ts` с простым примером (с пометкой, что полноценная проверка ещё не реализована). Позже научитесь отличать три состояния: **loading**, **error**, **ready**. Не показывайте пустой список во время загрузки, иначе пользователь не поймёт, что происходит.

**Важно:** на телефоне `localhost` — это телефон, а не сервер на вашем ноутбуке. Для подключения к локальному FastAPI задают `EXPO_PUBLIC_API_URL` с LAN-адресом компьютера, запускающего сервер. Пример в `.env.example`.

В учебном списке поле называется `durationMinutes`. Сервер может называть его иначе: проверяйте JSON и при необходимости преобразуйте данные. Для сетевого урока понадобится работающий тестовый API.
