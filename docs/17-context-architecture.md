# 17. Context и организация кода

Когда избранное нужно и главному экрану, и экрану деталей, не хочется передавать его через пять уровней props. **React Context** позволяет разделять состояние между вложенными компонентами.

В `AppProvider` настоящего MVP хранятся интересы, избранное, история, текущие рекомендации, состояния загрузки и ошибки. Экраны используют `useApp()`, а не вызывают SQL или базу напрямую.

Для упражнения можно завести маленький `FavoritesContext`, который хранит `string[]` ID и функцию `toggleFavorite`.

**Не начинайте с большого контекста:** сначала научитесь хранить состояние в одном компоненте и передавать props. Context решает конкретную проблему совместного использования данных, а не заменяет всю архитектуру.

Удобное разделение: `app/` — экран и навигация; `src/components/` — визуальные блоки; `src/lib/` — чистая логика; `src/api/` — запросы; `src/types/` — данные.
